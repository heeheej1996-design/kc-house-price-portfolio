# 킹 카운티 주택 가격 예측 — 오늘 한 일 정리

이 문서는 이 분야(데이터 분석·머신러닝)를 전혀 몰라도 오늘 무엇을 했고 왜 그렇게 판단했는지 알 수 있도록 쓴 리포트입니다.

## 1. 어떤 데이터이고 왜 골랐는지

미국 워싱턴주 **킹 카운티(King County)**에서 있었던 집 매매 기록입니다. 표의 한 줄이 집 한 채가 팔린 거래 하나이고, 언제·얼마에·방이 몇 개인 집이 팔렸는지 등이 담겨 있습니다. 원래 21,613건이 있었습니다.

결측치도 없고 값이 심하게 치우치지도 않아서 회귀분석 연습에 바로 적합한 데이터였습니다.

## 2. 어떤 문제를 정의했는지

### 후보 5개 중 왜 이걸 골랐는지

예측해볼 만한 주제 5개를 뽑아봤습니다: ① 집값 예측, ② 집 면적 예측, ③ 주변 집들 평균 면적 예측, ④ 대지 면적 예측, ⑤ 지하실 면적 예측. 이 중 ④, ⑤는 값이 0인 경우가 너무 많거나 극단치가 심해서 전처리에 시간이 오래 걸릴 것 같아 제외했고, 나머지 중 **① 집값(`price`) 예측**을 골랐습니다. 결측치도 없고 값이 심하게 치우치지도 않아서 바로 시작할 수 있는 주제였습니다.

### 문제 정의가 하루 동안 두 번 바뀌었습니다

**v0 (오전, 처음 정의)**
- 집 면적(`sqft_living`), 건축등급(`grade`), 지역(`zipcode`)으로 집값(`price`)을 예측
- 성공 기준: R²(설명력) 0.7 이상, 평균 오차가 중앙값 매매가(45만 달러)의 25% 이내

**v1 (오후, 첫 번째로 바뀐 것)**
- 극단치를 정리하면서 데이터의 성격 자체가 바뀌어(가격의 들쭉날쭉한 정도가 거의 절반으로 줄어듦), 오전에 정한 절대적인 숫자 기준이 더 이상 맞지 않게 됐습니다.
- 그래서 "아무 모델도 안 쓰고 그냥 평균값만 찍었을 때보다 나은가"를 기준으로 삼는 방식(기준선 비교)으로 바꿨습니다. 기준선의 오차(RMSE)는 195,080이었고, 이보다 낮으면 성공으로 정했습니다.
- 예측 대상, 입력 변수, 누구에게 쓸모 있는지는 바뀌지 않았습니다(그대로 유지).

**v2 (오후, 두 번째로 바뀐 것)**
- 데이터에 거래 날짜가 있다는 걸 다시 확인하면서, 데이터를 무작위로 훈련용/평가용으로 나누면 안 된다는 걸 깨달았습니다. 무작위로 나누면 평가용에 들어간 집의 앞뒤 날짜 거래가 훈련용에 섞여 들어가서, "미래를 보고 과거를 맞히는" 상황이 될 수 있기 때문입니다.
- 그래서 날짜순으로 정렬해서 앞 80%로 배우고 뒤 20%로 평가하는 방식으로 바꿨고, 기준선도 그 방식으로 다시 계산해서 195,257로 갱신했습니다.
- 나머지(예측 대상, 입력 변수, 사용 데이터)는 바뀌지 않았습니다.

## 3. 데이터에서 발견한 문제와 내 판단

데이터를 자세히 들여다보면서 5가지 문제를 발견했고, 각각 이렇게 판단했습니다.

| 발견한 문제 | 내 판단 | 이유 |
|---|---|---|
| 집값이 100만 달러 이상인 매물이 1,492건(전체의 6.9%) 있고, 최대값이 770만 달러까지 튐 | **삭제** | 이런 소수의 초고가 매물이 예측 오차를 크게 부풀리는 걸 확인했음(제외하니 오차가 19~41% 줄어듦) |
| 방 개수(`bedrooms`)가 33개인 집 1건 | **삭제** | 명백한 이상치로 보였고, 회귀분석에서 이런 값 1개가 결과를 크게 왜곡시킬 수 있어서 |
| 방(`bedrooms`)이나 화장실(`bathrooms`)이 0개인 집 16건 | **삭제** | 원인은 끝내 확인하지 못했지만(입력 실수인지 특수 매물인지 불명), 전체의 0.1%도 안 되는 소수라 삭제해도 손실이 적다고 판단 |
| 같은 `price` 컬럼 안에 숫자 표기 방식이 두 가지(`221900`처럼 일반적인 것과 `1.225e+006`처럼 과학적 표기법)로 섞여 있음 | **그대로 두기** | 값 자체는 틀리지 않았고, 프로그램이 둘 다 정상적으로 숫자로 읽어서 실질적인 문제가 아니었음 |
| 건축등급·건물상태 값 중 극히 드문 값들(예: 등급 1인 집 1건) | **그대로 두기** | 표본이 적긴 하지만, 이번 모델은 이런 등급을 범주가 아니라 그냥 숫자로 다뤄서 문제가 크지 않다고 판단 |

결측치(빈 칸)는 데이터 21개 컬럼 전부 0개였고, `?`나 `없음` 같은 위장된 결측값도 전수 조사했지만 하나도 없어서 별도 처리가 필요 없었습니다.

또한 "다른 컬럼을 조합하면 정답(집값)이 그대로 나오는 컬럼이 있는가"도 확인했는데, 그런 컬럼은 없었습니다. 다만 `sqft_above`(지상층 면적)는 `sqft_living`(전체 실거주 면적)과 정보가 거의 겹쳐서 제외했습니다.

## 4. 확인하려던 질문 3가지 — 데이터는 뭐라고 답했나

**질문 1. 초고가 매물이 예측 오차를 얼마나 부풀리는가?**
→ 실제로 크게 부풀렸습니다. 100만 달러 이상 매물을 빼고 다시 계산하니 오차가 최대 41%까지 줄었습니다. **상식과 일치**하는 결과였고, 그래서 위 표처럼 삭제하기로 결정했습니다.

**질문 2. 집 면적과 가격의 관계가 정말 일직선(비례)인가?**
→ 대체로 그렇습니다. 면적이 4,000평방피트 정도까지는 "면적이 늘수록 가격도 비례해서 오른다"는 가정이 잘 맞았습니다. **다만 그 이상(초대형 평수)에서는 표본(매물 수)이 너무 적어서 확실하게 판단하지 못했습니다** — 이 부분은 확인 못 한 채로 남아 있습니다.

**질문 3. 지역(우편번호)마다 집값 차이가 실제로 큰가?**
→ 네, 컸습니다. 가장 저렴한 지역과 가장 비싼 지역의 중앙값 가격이 3.7배 차이 났습니다. **상식과 일치**합니다. 다만 "어떤 지역이 통계적으로 확실히 다르고 어떤 지역은 그냥 우연에 가까운 차이인지"까지는 정식으로 검정하지 않고 그래프로만 확인했습니다.

**가장 의외였던 발견**: 건물 상태 등급(`condition`)은 집값과 거의 관계가 없었습니다(상관관계 거의 0). "상태 좋은 집이 더 비쌀 것"이라는 직관과 어긋나는 결과라, 오늘 발견한 것 중 가장 흥미로운 지점이었습니다. 비슷하게, 방 개수(`bedrooms`)가 많을수록 오히려 가격이 낮게 나오는 이상한 신호도 있었는데, 이건 아마 "면적"이라는 정보를 이미 다른 변수(`sqft_living`)가 다 담고 있어서 방 개수가 추가로 줄 정보가 별로 없기 때문으로 보입니다. 이 부분의 정확한 원인은 끝까지 확인하지 못했습니다.

## 5. 기준선 대비 성능이 어땠는지

"아무 모델도 안 쓰고 평균값만 찍었을 때"(기준선)와 비교해서, 실제로 3가지 방법(선형회귀 / 랜덤포레스트 / XGBoost)으로 예측했을 때 얼마나 나아졌는지 봤습니다.

| 방법 | 평균 오차(RMSE) | 기준선 대비 개선 |
|---|---|---|
| 기준선 (평균값만 찍기) | 195,257달러 | - |
| 선형회귀 | 88,477달러 | 54.7% 감소 |
| XGBoost | 82,574달러 | 57.7% 감소 |
| **랜덤포레스트 (가장 좋음)** | **81,472달러** | **58.3% 감소** |

셋 다 기준선보다 확실히 좋았고, 그중 **랜덤포레스트가 가장 정확했습니다.** 이 모델의 평균 오차(58,176달러, MAE 기준)는 집값 평균(46만 7천 달러)의 약 12.5% 수준입니다. 정확한 감정가를 대신할 수준은 아니지만, "이 집이 비싸게 나온 건지 싸게 나온 건지" 대략 가늠하는 용도로는 실무에 쓸 만하다고 판단했습니다.

랜덤포레스트에서 가장 중요했던 변수는 **위도(`lat`, 남북 위치)**와 **집 면적(`sqft_living`)**이었습니다. 위도가 중요한 이유를 지도로 확인해보니, 시애틀·벨뷰처럼 북쪽 도심 지역이 켄트·오번 같은 남쪽 지역보다 집값이 뚜렷하게 비쌌습니다 — 우연이 아니라 실제 지리적 패턴이었습니다.

**한 가지 한계**: 예측이 가장 크게 틀렸던 집 5채를 따로 봤더니, 전부 "작고 오래됐지만 시애틀 인기 동네에 있어서 비싸게 팔린 집"이었습니다. 이런 집들을 더 잘 맞히려고 "동네 평균 가격" 같은 새 정보를 추가해봤지만, 이 5채는 같은 동네 평균보다도 1.6~2.5배 비싼 진짜 예외적인 경우라 크게 개선되지 않았습니다. 전체 성능은 조금 더 좋아졌지만(오차 1.2% 추가 감소), 이런 극단적인 경우까지 맞히려면 지금 데이터에 없는 정보(조망, 리모델링 상세, 학군 등)가 필요해 보입니다.

## 6. 다음 단계로 필요한 것

- 랜덤포레스트, XGBoost는 기본 설정으로만 돌려봐서, 세부 옵션을 조정하면 더 좋아질 여지가 있습니다.
- 거래 날짜에서 "몇 년, 몇 월"처럼 더 세부적인 정보를 뽑아내 모델에 추가해볼 수 있습니다.
- 방/화장실 개수가 0인 집 16건이 왜 그런 값을 가졌는지 원인을 확인하지 못했는데, 시간이 되면 살펴볼 필요가 있습니다.
- "동네 평균 가격" 같은 지역 정보를 더 정교하게 다듬으면(예: 더 세밀한 지역 단위로 쪼개기) 성능이 조금 더 나아질 수 있습니다.
- 건물 상태(`condition`)가 왜 가격과 무관하게 나오는지는 아직 원인을 밝히지 못한 채로 남아 있어, 궁금하면 추가로 들여다볼 만합니다.
